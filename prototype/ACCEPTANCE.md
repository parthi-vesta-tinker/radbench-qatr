# Foundation acceptance gates

## Completed

- **F1 — contracts and storage:** fresh schema, one public API version, generated contracts, immutable snapshots/results, tenant-safe idempotency, and controlled regression tests.
- **F2 — content and snapshots:** pinned qatr sources/catalog, server-controlled tenant releases, complete immutable composition, Studio source/catalog visibility, and package/hash validation.
- **F3 — execution:** one combined call, truthful phases, durable claim/response handling, no automatic ambiguous retry, context-bound admission, recovery tests, frontend regression, and source bundle checks.

## F4 — product regression and handoff

- Exercise the full new-report, completion, copy, history, feedback, outcomes, analytics, and Skills Studio paths on fresh storage.
- Review keyboard, narrow layout, light/dark contrast, health details, error messages, and unknown-outcome operator guidance.
- Confirm generated contracts, documentation boundary, package validation, manifest, and distributable source bundle.
- Record actual commands, versions, screenshots where useful, and unresolved release risks in the implementation status.

## F5 — bounded model and clinical evaluation

- Predeclare the evaluation cases, model, and stopping rule.
- Separate provider connectivity, model-output evaluation, and qualified clinical adjudication.
- Preserve failures, indeterminate cases, denominators, immutable provenance, and release version. Do not turn feedback acceptance into an accuracy label.
- Do not claim clinical validation, production readiness, or patient-data suitability from technical tests.
