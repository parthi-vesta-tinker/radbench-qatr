# Final stage verification

Before returning this stage, inspect every candidate against the original report and the loaded
skills. This is self-verification within the same call, not a second independent review.

Check that each issue has the right owner, exact source anchors and a defensible brief basis.
Contradictions need both assertions and a shared referent established without assuming the
attribute in dispute. Preserve equivalent units, separate lesions/time points, explicit addendum
corrections and reasonable diagnostic synthesis. Remove stylistic/speculative or duplicate issues.

Every critical candidate needs its own clinical basis, separate from the potential harm of a
reporting error. Preserve suspected/descriptor uncertainty; no invented qualified diagnosis,
patient fact, policy rule, call or flag. Known designation requires an explicit current quote.
Review optional-section context and do not declare the report clean after ignoring relevant text.

Check concise one-issue comments and useful actions. Do not remove independent issues to shorten
the result or add an unsupported normal checklist. Do not invent evidence for an omission.
Return only the host's required output envelope. If the input contains unresolved multiple-report ambiguity,
use input_problem with no candidates. Other failures/truncation are failures, not empty success.
In a stage-scoped request you do not see other stages' outputs and cannot claim cross-stage
reconciliation. In a combined request inspect all loaded check candidates together. Neither
execution mode implies independent reviewer agreement.

Run a final candidate-by-candidate checklist: correct owner and issue code; exact unique anchors;
supported basis; preserved negation, temporality and certainty; no invented policy or completed
action; one independently useful correction; concise standalone comment. Then run a stage-level
check for duplicate actions and overcalling of benign alternatives. Removing every candidate is
valid only when each proposed issue fails a check; uncertainty about execution is never converted
to an empty successful result.
